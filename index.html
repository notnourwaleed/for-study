Introduction to Computer Networks

1.1

What is a computer network?

In plain wordsA network is like a road system for data. Your devices are the houses, the cables and Wi-Fi are the roads, and the data is the deliveries going between them. Without the roads, every house is on its own.

A computer network is a system of connected devices, such as computers, servers and routers, that communicate with each other to share data, resources and services.

You already use several. The Internet is the largest network in the world. Your home Wi-Fi connects your phone, laptop and smart devices. Companies run corporate networks for secure internal communication, and data centres and cloud networks power services like Google Drive and AWS.

Networks shape daily life. Social media and messaging run on them: WhatsApp, Instagram, and video calls on Zoom or Teams. So do cloud storage and computing, like Google Drive, OneDrive, AWS and Azure, which let companies host apps without owning the hardware. Remote work depends on VPNs for secure access, on tools like Google Docs, Slack and Trello, and on remote desktop for IT support.

Networks also bring threats: phishing, DDoS attacks and ransomware. Organisations defend themselves with security protocols such as SSL/TLS and IPSec, with firewalls, and with Zero Trust Architecture, which trusts no device by default.

1.2

Types of network by size

In plain wordsThink of network sizes like places. A PAN fits in your pocket, a LAN fills a home or office, a CAN covers a campus, a MAN covers a city, and a WAN spans countries. Each one is bigger than the last.

Your lab groups networks in three ways: by size, by implementation (client-server or peer-to-peer), and by transmission media (wired or wireless). We start with size, from smallest to largest.

PAN · Personal Area Network
A tiny network with a range of a few metres, connecting one person's devices. Examples: Bluetooth earbuds or a smartwatch, your phone's personal hotspot, an infrared TV remote.
LAN · Local Area Network
Devices in a limited area like a home, office or school, usually sharing printers, files and one Internet connection. Examples: home Wi-Fi, an office or university lab, a LAN gaming party.
CAN · Campus Area Network
Several LANs joined together inside one defined boundary, owned and managed by whoever owns the campus. Examples: a university campus linking halls, libraries and dorms; a corporate park; a hospital complex.
MAN · Metropolitan Area Network
Covers a city. Bigger than a LAN, smaller than a WAN, typically linking many buildings across a metro area. Examples: city-wide public Wi-Fi, an Internet provider's fibre network across a city.
WAN · Wide Area Network
Connects LANs and MANs across cities, countries or the whole globe. The Internet is the largest WAN. Others: corporate networks linking offices worldwide, and satellite networks.

Exam tipThe classic trap is CAN versus MAN. A CAN has one owner inside one boundary, like your university. A MAN covers a whole city. Your MAN slide also lists "university campus networks" as an example, so if a question says several LANs inside one organisation's site, answer CAN.

In plain wordsWired is like a water pipe: fast and steady, but you have to be connected to it. Wireless is like a radio broadcast: you can move around freely, but the signal can be weaker, and anyone nearby can try to listen.

Classified by transmission media, a network is either wired or wireless.

1.4

Client-server and peer-to-peer

In plain wordsClient-server is like a restaurant. The customers, the clients, order, and one kitchen, the server, cooks for everyone. Peer-to-peer is like a potluck dinner: everyone brings food and everyone takes some, with no single kitchen.

Classified by implementation, there are two models. In the client-server model, one machine, the server, provides services or resources, and other machines, the clients, request and use them.

The client starts the conversation. It sends requests and waits for the server's response. Web browsers, email apps and online games are clients. The server listens for requests, processes them and sends back responses, usually to many clients at once. Web servers, mail servers and file servers are examples.

Common client-server protocols: HTTP and HTTPS for the web, SMTP, IMAP and POP3 for email, FTP for file transfer, and DNS for turning domain names into addresses.

Advantages: data and resources are managed in one place, maintenance and updates are easier, and security is controlled at the server. Disadvantages: if the server fails, every client is affected; the server can become a bottleneck under heavy load; and servers are expensive to buy and maintain.

In the peer-to-peer model, or P2P, there is no central server. Every device, called a peer, acts as both a client and a server, and peers share directly with each other.

File sharing with BitTorrent shows how it works. A peer wants a file, so it searches the network for peers that have it. It downloads the file in pieces from several peers at once. Once it has pieces, it shares them with others too.

Advantages of P2P: no server cost, every peer contributes resources, it scales well because more peers means more capacity, and it is fault tolerant because the network keeps working if some peers leave. Disadvantages: security is hard to control, keeping data consistent is difficult, performance depends on which peers are online, and it is often used for illegal file sharing.

1.5

Network devices

In plain wordsPicture three helpers passing on messages. A hub shouts every message to the whole room. A switch is a receptionist who hands each message to the right person in the building. A router is a post office that sends messages on to other towns.

Hub Layer 1
A simple box that copies every piece of data to all connected devices, without checking who it is for. It is largely obsolete today.
Switch Layer 2
Connects devices inside a LAN. It is smart: it forwards data only to the intended recipient instead of sending it to everyone.
Router Layer 3
Directs traffic between different networks, and works out the best path for data to travel from source to destination.
Access point
Extends Wi-Fi coverage by giving wireless access to a wired network.
NIC · Network Interface Card
The hardware inside a device that lets it connect to a network, either wired through Ethernet or wireless through Wi-Fi.
Firewall
Hardware or software that watches network traffic and allows or blocks it using security rules. It is the barrier between a trusted internal network and an untrusted one like the Internet. It protects against unauthorised access, helps stop malware, DDoS and ransomware, enforces company policies like blocking malicious websites, and supports network segmentation to isolate sensitive data.

RememberHub is layer 1, switch is layer 2, router is layer 3. These layer numbers come back in the OSI model in Week 3.

1.6

Protocols and network commands

In plain wordsA protocol is like the rules of a conversation in a shared language: who speaks first, how to greet, how to say goodbye. Without agreed rules, a Windows laptop and a Linux server would not understand each other.

A protocol is a set of rules and standards that define how devices on a network communicate. It makes sure data is sent, received and understood correctly between different systems.

Protocols define how data is formatted, transmitted and received. They let different devices, like Windows, Mac and Linux machines, talk to each other. They keep data intact, and some encrypt it to protect it.

  • Communication protocols: TCP/IP, HTTP, FTP, SMTP.
  • Security protocols: SSL/TLS, IPSec.
  • Routing protocols: BGP, OSPF, RIP.
  • Wireless protocols: Wi-Fi, which is 802.11, and Bluetooth.

1.7

The network edge

In plain wordsThink of the Internet as a city. The end systems are the houses and offices at the edges, where people live and work. The network core is the roads and junctions in the middle that connect them all.

The computers and other devices connected to the Internet are called end systems, because they sit at the edge of the Internet. They include desktop PCs, servers such as web and email servers, laptops, smartphones and tablets, and more and more everyday "things".

End systems are also called hosts, because they host, meaning they run, application programs: a web browser, a web server, an email client or an email server.

The Internet of Things, or IoT, is the idea that nearly everything gets connected: cars, watches, glasses, toys, hospital equipment, home sensors, even pets. Smart watches and Internet-connected thermostats you control from your phone already exist.

IoT has big benefits but also big security and privacy risks. Attackers could hack the devices or the servers collecting their data. Your slides give two examples: hijacking an Internet-connected doll to talk to a child, and stealing health data collected by wearables. Fears like these could slow down how widely IoT is adopted.

The big pictureThe Internet has three parts. The edge is the end systems. The access network is the link from an end system to its first router. The core is the mesh of routers that connects everything together.

1.8

Access networks: DSL, fibre and Ethernet

In plain wordsThe access network is like your driveway: the short road from your house to the main road. However fast the motorways are, every trip starts on your driveway, so its speed matters a lot.

An access network is the network that physically connects an end system to the first router, called the edge router, on the path to any distant end system.

DSL

DSL reuses the existing telephone line, which is twisted-pair copper wire. The DSL modem at home turns digital data into high-frequency tones and sends them down the phone line to a DSLAM, a digital subscriber line access multiplexer, in the phone company's local central office. The DSLAM turns the signals from many homes back into digital data.

DSL standards include 12 Mbps down and 1.8 Mbps up, or 55 Mbps down and 15 Mbps up. Because download and upload speeds differ, DSL is called asymmetric.

The real speed is also limited by the distance from home to the central office, the thickness, or gauge, of the copper wire, and electrical interference. DSL is designed for short distances: homes more than about 5 to 10 miles from the central office need another type of access.

FTTH: fibre to the home

FTTH gives an optical fibre path from the central office to the home, for much higher speeds. The simplest version, direct fibre, runs one fibre per home. More commonly, one fibre from the central office is shared by many homes and only split into separate fibres near the houses. Two architectures do this splitting: active optical networks, AONs, and passive optical networks, PONs.

In a PON, each home has an optical network terminator, the ONT. It connects by its own fibre to a neighbourhood splitter. The splitter combines fewer than 100 homes onto one shared fibre, which runs to the optical line terminator, the OLT, in the central office. The OLT converts between light and electrical signals and connects to the Internet through the telco's router.

FTTH can reach gigabits per second. Your slides quote 2011 US averages for comparison: about 20 Mbps for FTTH, 13 Mbps for cable and under 5 Mbps for DSL.

Enterprise access: Ethernet

In companies and universities, devices plug into Ethernet switches with twisted-pair cable, and those switches connect up to the organisation's router and on to the Internet.

Memory hookDSL: modem to DSLAM. Fibre: ONT to splitter to OLT. T for terminator: the ONT is at your home, the OLT is at the line's other end in the central office.

1.9

The network core and circuit switching

In plain wordsCircuit switching is like booking a private lane on every road from you to your friend before you set off. Nobody else can use that lane while it is yours, even when you stop to rest.

The network core is the mesh of switches and links that connects the Internet's end systems. There are two fundamental ways to move data through it: circuit switching and packet switching.

In circuit switching, the resources needed along the path, meaning buffers and link transmission rate, are reserved for the whole communication session.

Traditional telephone networks work this way. Before you can talk, the network must set up a connection between you and the other person. This connection is called a circuit. The network reserves a constant transmission rate on every link for the whole call, so data flows at a guaranteed constant rate.

Your lecture's example: four circuit switches joined by four links, and each link has four circuits, so it can carry four connections at once. For Host A to talk to Host B, the network reserves one circuit on each of the two links on the path: the second circuit on the first link and the fourth circuit on the second link.

Each connection gets one quarter of each link's capacity for the whole call. If each link is 1 Mbps, each connection gets a dedicated 250 kbps.

rate per circuit = link rate ÷ circuits = 1 Mbps ÷ 4 = 250 kbps

1.10

FDM: sharing a link by frequency

In circuit switching, one link is shared by several connections at once. There are two ways to divide it up: by frequency, or by time.

This lesson covers the first way, frequency-division multiplexing, or FDM.

Think of radio. Every station broadcasts all the time, but each one uses its own frequency, so they never get in each other's way.

FDM works the same way. The link's frequency range is cut into bands, and each connection keeps its own band for the whole call.

In one lineFDM: everyone transmits at the same time, each in their own band.

RememberA band stays reserved even when its owner is silent. Nobody else can use it, so that capacity is wasted.

1.11

TDM: frames and slots

The second way to share a link is time-division multiplexing, or TDM. Instead of splitting frequencies, the connections take turns.

Picture four friends sharing one microphone. Each one speaks for one second, always in the same order, and then it goes round again.

One full round is called a frame. Each person's turn inside it is called a slot.

A connection owns the same slot in every frame. If slot two is yours, it is yours in every round.

Frames repeat at a fixed rate, for example 1000 frames per second.

If eight devices share the link instead of four, each frame gets eight slots. There are still 1000 frames per second.

So adding devices adds slots to each frame, not more frames. Each turn gets shorter, and everyone gets a smaller share of the link.

Exactly. The frames keep the same rhythm. Only the number of slots inside each frame changes.

1.13

TDM: the lecture's worked example

Worked example from the lecture

How long does it take to send a 640,000-bit file from Host A to Host B? Every link uses TDM with 24 slots and a bit rate of 1.536 Mbps, and setting up the circuit takes 500 milliseconds.

  1. Each slot gets 1,536,000 bps ÷ 24 = 64,000 bps. That is Host A's rate, because it owns one slot.
  2. Transmission time = 640,000 bits ÷ 64,000 bps = 10 s.
  3. Total time = setup + transmission = 0.5 s + 10 s = 10.5 s.

The lecture also writes the circuit rate another way: frame rate times bits per slot. It gives the same answer.

circuit rate = frame rate × bits per slot · e.g. 8,000 × 8 = 64 kbps

Common mistakes
  • Dividing the file by the link rate, 1.536 Mbps, instead of your slot's rate.
  • Forgetting to add the setup time.
  • Adding 500 milliseconds to 10 seconds as if both were seconds.
1.14

Packet switching and store-and-forward

In plain wordsPacket switching is like sending a long book as a pile of separate postcards. Each postcard travels on its own, and every post office waits until it holds a whole postcard before passing it on.

In a network application, end systems exchange messages. A message can carry control information, like a "Hi", or data, like an email, a JPEG image or an MP3 file. To send a long message, the source breaks it into smaller chunks called packets.

Between source and destination, each packet travels across links and through packet switches, such as routers. A packet is sent over each link at that link's full transmission rate. So if a packet has L bits and the link rate is R bits per second, transmitting it takes L divided by R seconds.

transmission time = L / R  (L in bits, R in bits per second)

Most packet switches use store-and-forward transmission. The switch must receive the entire packet before it can start sending the first bit onto the next link.

Follow one packet over two equal links, ignoring propagation. At time zero the source starts sending. At time L/R the source has sent the whole packet, and the router has received and stored all of it. Only now can the router start sending it on. At time 2L/R the router has sent it all, and the destination has the whole packet.

Rule for exercisesStore-and-forward adds one transmission time per link. With different link rates, add each link's L/R. Tutorial 2 drills this.

1.15

Buffers, queuing delay and packet loss

In plain wordsA router's buffer is like the queue at a supermarket checkout. If shoppers arrive faster than the cashier can serve them, the line grows. If the line has no more room, new shoppers are turned away. That is packet loss.

A buffer is temporary storage inside a switch or router where packets wait before being forwarded. With input buffering, packets wait at the input ports before processing. With output buffering, packets wait at an output port when several incoming packets all need the same outgoing link.

Output buffers are key to packet switching. If a packet arrives and its outgoing link is busy sending another packet, it waits in the output buffer. So on top of store-and-forward delay, packets suffer queuing delay. It varies and depends on how congested the network is.

A buffer has limited space. If a packet arrives when the buffer is already full, it has nowhere to go and is dropped. This is packet loss.

Worked example from the lecture

A switch has 4 input ports and 1 output port. The output port sends at 1 Gbps. Each input sends 1000-byte packets at 400 Mbps, all headed for the same output. The output buffer holds 100 packets.

  1. Total arrival rate = 4 × 400 Mbps = 1600 Mbps.
  2. The output can only send 1 Gbps, which is 1000 Mbps.
  3. Excess = 1600 − 1000 = 600 Mbps that cannot be sent straight away, so it queues in the output buffer.
  4. One step further than the slides: the buffer holds 100 × 8,000 bits = 800,000 bits. Filling it at 600 Mbps takes 800,000 ÷ 600,000,000 ≈ 1.33 ms. After that, packets are dropped.

Try it in the simulator. Change how many input ports are sending and watch the buffer.

2.1

Recap, and the three performance metrics

In plain wordsThink of a delivery company. Delay is how long one parcel takes. Loss is how many parcels never arrive. Throughput is how many parcels actually arrive per hour. Those three numbers tell you how good the service is.

2.2

The four delays at every hop

In plain wordsPicture a convoy of cars going through a toll booth. Processing is the officer checking your ticket. Queuing is waiting in line at the booth. Transmission is the time for the whole convoy to drive through the gate. Propagation is the drive along the road to the next booth.

With store-and-forward, every router receives the whole packet, stores it in memory, processes it, and forwards it to the next hop. So every hop adds its own four delays.

Processing delay
Time for the router to check the packet's header, work out where it is going, check for bit errors with something like CRC, and look up the route. Example: 0.5 ms.
Queuing delay
Time spent waiting in the output queue before transmission. It depends on traffic load, buffer size and the scheduling algorithm. It is highly variable: near 0 ms on an idle link, tens to hundreds of milliseconds when congested. Example: 120 ms.
Transmission delay
Time to push all of the packet's bits onto the link. It depends on packet size and link rate. Example: a 1,000-byte packet is 8,000 bits; on a 1 Mbps link that takes 8,000 ÷ 1,000,000 = 0.008 s, which is 8 ms.
Propagation delay
Time for one bit to travel through the medium, whether copper, fibre or air, to the next node. It depends on distance and propagation speed. Example: 1,000 km at 2 × 10⁸ m/s takes 1,000,000 ÷ 200,000,000 = 0.005 s, which is 5 ms.

dtrans = L / R   ·   dprop = d / s

Don't mix these two upTransmission delay is how long it takes to push the packet out of the door. It depends on packet size and link rate, not on distance. Propagation delay is how long one bit takes to travel down the cable. It depends on distance and the medium, not on packet size. Think of a convoy of cars at a toll booth: the time for the whole convoy to pass the booth is transmission; the drive to the next booth is propagation.

Signals in copper and fibre travel at roughly 2 × 10⁸ m/s, a bit slower than the speed of light in air, about 3 × 10⁸ m/s. Use the values from your slide's propagation speed table when the exam gives them.

2.3

Packet loss

In plain wordsThink of a bucket with a hole in the bottom, under a running tap. If water pours in faster than the hole lets it out, the bucket fills up, and then it overflows. The water that spills over is packet loss.

Packet loss means one or more packets never reach their destination, so the receiver gets incomplete or missing information.

The main cause is router queue overflow. A router keeps arriving packets in a queue before sending them out. When the queue is full, new packets are dropped. This happens under heavy traffic, or congestion. If a router can hold 10 packets and 12 arrive in a burst, it drops 2.

Three things matter. The sending rate S is how fast the sender pushes packets into the network. The transmission rate T is the maximum speed the link can handle, its bandwidth. The queue size Q is how many packets the router can hold while congested.

loss happens when S > T and the buffer is full

Worked example from the lecture

Link rate T is 10 Mbps. Sending rate S is 20 Mbps. The router queue holds 100 packets. Each packet is 1,000 bytes, which is 8,000 bits. We watch for 1 second.

  1. Sent: 20,000,000 bits ÷ 8,000 = 2,500 packets.
  2. Forwarded by the link: 10,000,000 bits ÷ 8,000 = 1,250 packets.
  3. Extra packets arriving at the router: 2,500 − 1,250 = 1,250.
  4. The queue can hold 100 of them, so the rest are dropped: 1,250 − 100 = 1,150 packets lost.

What happens next depends on the transport protocol. TCP notices the loss through missing acknowledgements or timeouts and retransmits the lost packets, so delivery is reliable. UDP does not retransmit: lost packets are gone for good. That is acceptable for video calls, online games and live streaming, which prefer speed over perfection.

2.4

Throughput, bandwidth and bottlenecks

Throughput, also called data transfer rate, is the amount of data that actually arrives successfully at the destination over a period of time. It is measured in bits per second, or packets per second.

Bandwidth is the maximum amount of data that could travel across the network in that time. It is the capacity, not the actual performance.

For example, a cable supports up to 100 Mbps: that is its bandwidth. Because of congestion and delays, the data actually moves at 65 Mbps: that is the throughput.

Bottleneck throughput is the highest rate data can cross a whole path, and it is set by the slowest link on that path. Here is why.

Picture a roadA road has a 10-lane motorway, then a 2-lane bridge, then an 8-lane motorway. However many cars the first motorway carries, only as many as fit on the bridge get across each minute. The rest wait in a jam before the bridge, and the road after the bridge stays mostly empty.

Links work the same way. Take a path of 10 Mbps, then 2 Mbps, then 8 Mbps. Router A receives 10 megabits every second but can only send 2 megabits onward. The other 8 wait in its buffer, which is the queue from lesson 1.15, and if the buffer fills, packets are lost.

The 8 Mbps link after it only receives 2 megabits each second, so it sits mostly idle. It cannot carry data that never reaches it.

So a fast link before the slow one only builds a queue, and a fast link after it only waits. Either way, the receiver gets 2 Mbps. That is why we take the smallest rate.

end-to-end throughput = min(R1, R2, …)

Example: a server connects to a router over Link A at 100 Mbps, and the router connects to the client over Link B at 10 Mbps. Even though Link A is fast, the bottleneck throughput is 10 Mbps.

Check yourself

Worked example: how long does a file take?

Exams often ask how long a file takes to arrive. Divide the file size by the bottleneck rate. A 4 MB file crosses links of 10, 2 and 8 Mbps. Take 1 MB as 1,000,000 bytes.

  1. File size in bits: 4 × 1,000,000 × 8 = 32,000,000 bits.
  2. Bottleneck: min(10, 2, 8) = 2 Mbps, which is 2,000,000 bits per second.
  3. Time: 32,000,000 ÷ 2,000,000 = 16 seconds.

Common causes of bottlenecks: old cables or switches, such as 10 or 100 Mbps equipment; wireless interference or a weak signal; routers or firewalls overloaded with too many flows; Internet provider speed limits; and cloud server limits on outgoing bandwidth.

3.1

Why layers, and the seven OSI layers

One story for the whole weekThis week we follow one request all the way through. You type google.com into your browser and press Enter. Seven jobs have to happen before Google even sees it, and each OSI layer does one of them.

Think of posting a letter. You write it, put it in an envelope, write the address, and the post office moves it van by van. Each step wraps the message in a little more information, and the person who receives it unwraps it in the opposite order. Each wrapper is a layer.

Network layers split the job of communicating into structured pieces. Each layer has one responsibility, which makes systems from different vendors work together.

Standardisation
Devices from different manufacturers can communicate seamlessly.
Troubleshooting
You can find a problem faster by isolating it to one layer.
Security
Protection can be added at several layers, which strengthens the whole network.

There are two network models: the OSI model, Open Systems Interconnection, and the TCP/IP model.

The OSI model is a conceptual framework from the International Organization for Standardization, ISO. It has seven layers, each with a specific job, from physically sending bits up to the applications people use. It helps us design, troubleshoot and understand networks.

Compression and decompression

Turns readable plaintext into unreadable ciphertext so nobody can eavesdrop, and the receiver decrypts it back. When you visit an HTTPS site, SSL/TLS encrypts the data. WhatsApp and Signal use end-to-end encryption. Common protocols and algorithms: SSL/TLS, AES, DES and RSA.
Formatting and syntax

3.4

Layer 5: Session

On the journeyNow your browser needs an open conversation with Google's server, one that lasts while you click around the site. The Session layer opens that conversation, keeps it going, and closes it neatly at the end. It is like a phone call: you dial, you talk, and you hang up.

The Session layer sets up, manages and ends communication sessions between two devices or applications. It keeps a session active and synchronised, and closes it properly when it is no longer needed.

It also controls the direction data can flow.

Simplex
One side only sends and the other only receives, like a keyboard sending to a computer, or a TV broadcast.
Half-duplex
Both sides can send, but they take turns, like a walkie-talkie.
Full-duplex
Both sides send and receive at the same time, like a phone call.

In one line: open, keep and close the conversation. Next, layer 4 chops the data up and labels it.

3.5

Layer 4: Transport, TCP and UDP

On the journeyYour request may be too big to send in one piece. The Transport layer cuts it into numbered segments and labels each one with port numbers. Port 443 on Google's side makes sure it reaches the web server program, not the mail program.

It also chooses how careful to be. TCP is like registered mail: every piece is numbered, confirmed, and sent again if it gets lost. UDP is like shouting across a room: fast, but nobody checks that it arrived. A web page uses TCP, so nothing goes missing.

The Transport layer handles end-to-end communication between devices. It makes sure data arrives correctly, in order and without errors. It does three main things.

Segmentation and reassembly
It breaks application data into chunks called segments and gives each a sequence number, so the receiver can put them back together in the right order, for example when you download a large file.
Flow control
It stops a fast sender from overwhelming a slow receiver, using windowing, the sliding window protocol, to limit how much is sent before an acknowledgement comes back.
Error detection and correction
It uses checksums to spot damaged segments, and lost or corrupted data is sent again.
TCP, the reliable one

TCP, Transmission Control Protocol, is connection-oriented. It sets up a connection before sending data and guarantees that everything arrives, in order, without errors. It does this with acknowledgements called ACKs, error checking, retransmission of lost packets, and flow control. Web browsing, email and file transfer use it. The cost is speed: TCP is slower than UDP.

TCP opens a connection with a three-way handshake. The client sends SYN. The server replies SYN-ACK. The client answers ACK. Now data can flow.

3.6

Ports, processes and sockets

On the journeyYour laptop runs many network apps at once: the browser, WhatsApp, a game. When Google's reply comes back, the port number tells your computer which app it belongs to. It is like a block of flats: the street address gets the letter to the building, and the flat number gets it to the right door.

One computer runs many network apps at once. Ports tell the Transport layer which app each piece of data belongs to. A port is a 16-bit number, from 0 to 65,535, assigned to a process or service.

When you visit a website, your device sends the request to the server's IP address on port 80 for HTTP or 443 for HTTPS, and the server's web service handles it.

A process is a running instance of a program. One app can run several processes: Google Chrome, for example, runs each tab as its own process. A process can open network connections, send and receive data, and use memory, CPU and ports.

A socket is the software doorway between a process and the network. It is an interface, or API, provided by the operating system that sits between the Application layer and the Transport layer. A complete socket address has three parts: the IP address, which identifies the host; the port number, which identifies the service; and the protocol, TCP or UDP.

Example: your email app connects to the mail server's IP address on port 993, which is IMAP over SSL. That combination makes sure your data reaches the right service on the right machine.

In one line: the IP address finds the computer, and the port finds the program. Next, layer 3 adds those IP addresses.

3.7

Layer 3: Network

On the journeyEach segment now gets a full address label: your IP address as the sender, and Google's IP address as the destination. Now it is called a packet. Routers read the destination IP and pass the packet on, hop by hop, like post offices forwarding a letter from city to city. The IP addresses stay the same for the whole trip.

The Network layer handles logical addressing, routing and forwarding, so packets get from source to destination even across different networks. Routers work at this layer.

Logical addressing
Every device gets an IP address. An email from New York to London crosses many networks, guided by IP addresses.
Routing
Working out the best path. Routers use routing tables and algorithms such as OSPF, BGP and RIP.
Forwarding
Each router checks the destination IP address and passes the packet to the next router, hop by hop, until it arrives.
Network layer protocols
  • IPv4 uses 32-bit addresses, like 192.168.1.1.
  • IPv6 uses 128-bit addresses, like 2001:db8::ff00:42:8329, giving far more address space.
  • ICMP, Internet Control Message Protocol, reports errors and runs diagnostics. The ping command uses it.
  • IGMP, Internet Group Management Protocol, manages multicast groups for one-to-many delivery, used in video streaming and online gaming.

In one line: IP addresses, and the route across many networks. Next, layer 2 handles just the next hop.

3.8

Layer 2: Data Link

On the journeyIP gets the packet across the world, but each step still has to reach one specific machine: from your laptop to your home router, then from router to router. The Data Link layer wraps the packet in a frame with MAC addresses for just that one hop. At every router the old frame is removed and a new one is made, so the MAC addresses change at every hop while the IP addresses stay the same.

When devices share one medium, like Wi-Fi, they must take turns. They listen before they talk, like polite people in a meeting. If two talk at once, that is a collision, and both wait a random time and try again.

Watch the MAC addresses change, hop by hop

Take a simple path: your laptop, router A, router B, then Google's server. Every network card has its own MAC address, and a router has one card for each side. Call them L for your laptop, A1 and A2 for router A, B1 and B2 for router B, and G for Google's server.

  1. Your laptop builds a frame: source MAC L, destination MAC A1. Inside is your packet, from your IP address to Google's IP address.
  2. Router A sees the destination MAC A1, its own address, so it accepts the frame. It then removes the MAC header and trailer. Only the packet is left.
  3. Router A reads the destination IP address, Google, and its routing table says the next hop is router B.
  4. Router A wraps the same packet in a brand new frame: source MAC A2, its own outgoing card, and destination MAC B1, router B.
  5. Router B does exactly the same: removes the frame, reads the IP address, and builds a new frame from B2 to G.
  6. Google's server accepts the frame addressed to G, removes it, and finds your packet, still from your IP address to Google's IP address.

Why it works this wayA MAC address only describes one hop: who is sending this frame on this wire, and who should pick it up at the other end. The IP addresses describe the whole journey, so they never change.

Think of a parcel going through courier depots. The address written on the parcel, the IP address, stays the same all the way. At every depot, the old delivery sticker is torn off and a new one is stuck on, saying from this depot to the next one. That sticker is the MAC header. Routers find the next device's MAC address using ARP, which comes at the end of this lesson.

The Data Link layer handles node-to-node delivery across one physical link, such as an Ethernet cable or a Wi-Fi connection. Switches work at this layer.

Framing
It wraps the packet from the Network layer into a frame. A frame holds the source and destination MAC addresses, the data payload, and error-checking information.
Physical addressing
It uses MAC addresses for local delivery, while the Network layer uses IP addresses for global delivery. Every network card, the NIC, has its own unique MAC address. A switch uses MAC addresses to send each frame out of the right port.
Error detection
It uses a Cyclic Redundancy Check, CRC, to catch errors in transmission.
Media access control
It decides who may use the medium. CSMA/CD, collision detection, is used in wired Ethernet: it detects collisions and handles them. CSMA/CA, collision avoidance, is used in Wi-Fi: it tries to avoid collisions before they happen.
Data Link protocols
  • Ethernet, IEEE 802.3: the most common wired LAN protocol. Uses MAC addresses and CSMA/CD.
  • Wi-Fi, IEEE 802.11: the most common wireless LAN protocol. Uses CSMA/CA.
  • ARP, Address Resolution Protocol: translates an IP address into a MAC address on the local network. For example, your computer uses ARP to find the printer's MAC address before sending it data.

In one line: MAC addresses, the next hop only, and catching damaged frames. Next, layer 1 turns it all into signals.

3.9

Layer 1: Physical, and transmission media

On the journeyFinally, your frame is just ones and zeros. The Physical layer turns them into something that can travel: electrical pulses in a copper cable, flashes of light in fibre, or radio waves over your Wi-Fi.

The Physical layer is the lowest layer. It sends the raw bits, the ones and zeros, over a physical medium: electrical signals in copper, light pulses in fibre, or radio waves in wireless. It defines the hardware, cables, connectors and how signals are encoded.

Twisted-pair copper
The cheapest and most common wired medium, used by telephone networks for over a hundred years. Two insulated copper wires, each about 1 mm thick, are twisted in a spiral to reduce electrical interference from nearby pairs. Unshielded twisted pair, UTP, is used for LANs inside buildings, at 10 Mbps up to 10 Gbps depending on wire thickness and distance.
Coaxial cable
Also two copper conductors, but concentric, one inside the other, rather than side by side. With special insulation and shielding it reaches high data rates. Common in cable TV.
Fibre optics
A thin, flexible strand that carries pulses of light, each pulse a bit. It supports tens to hundreds of gigabits per second, is immune to electromagnetic interference, loses very little signal over up to 100 km, and is very hard to tap.

Optical Carrier standards are written OC-n, where the speed is n × 51.8 Mbps. They range from OC-1 at 51.8 Mbps to OC-768 at 39.8 Gbps. Standards in use include OC-1, OC-3, OC-12, OC-24, OC-48, OC-96, OC-192 and OC-768.

OC-n = n × 51.8 Mbps  ·  OC-3 = 3 × 51.8 = 155.4 Mbps

In one line: bits become signals on a wire, a fibre or the air. At Google's end the signals are turned back into bits, and everything is unwrapped going up.

3.10

Physical topologies

The Physical layer also defines the topology: how devices are connected.

Bus
All devices share one cable. Used in old Ethernet networks.
Star
Every device connects to a central hub or switch. This is modern Ethernet.
Ring
Data travels around a circular loop. Used in old Token Ring networks.
Mesh
Devices are interconnected with many paths between them. Used where reliability matters most, like the Internet.
3.11

Encapsulation

The whole tripNow put the whole trip together. Going down on your laptop, each layer wraps what it got from above, like putting a letter in an envelope, then in a parcel, then in a mail sack.

Encapsulation is how data gets wrapped as it moves down the layers. Each layer adds its own header, its control information, around what it received from the layer above. Some add a trailer at the end too.

  1. Application, layer 7, creates the original data, like an email or a web request.
  2. Presentation, layer 6, puts it in the right format, encrypting or compressing it.
  3. Session, layer 5, manages the session between the devices.
  4. Transport, layer 4, splits the data into segments and adds a TCP or UDP header with the source and destination ports.
  5. Network, layer 3, wraps the segment into a packet and adds an IP header with the source and destination IP addresses.
  6. Data Link, layer 2, wraps the packet into a frame with a MAC header, holding the source and destination MAC addresses, and often a trailer for error checking.
  7. Physical, layer 1, turns the frame into electrical, light or radio signals.

The receiver does the reverse, called decapsulation: each layer strips off its own header and passes the rest up.

Names of the data unitSegment at layer 4, packet at layer 3, frame at layer 2, bits at layer 1. Questions love asking for these.

On the way, at every router, the frame is opened up to layer 3. The router reads the destination IP address, then wraps the packet in a brand new frame for the next hop. Only the MAC addresses change. The IP addresses and ports stay the same from start to finish.

At Google's server the wrappers come off going up: bits, frame, packet, segment, and finally your HTTP request. Google then sends the page back to you the same way, in the opposite direction.

3.12

The TCP/IP model

Same trip, fewer layersReal networks follow the simpler TCP/IP model. It is the same journey you just followed, with some of the OSI jobs grouped together.

The TCP/IP model is a simpler, practical framework that describes how data actually moves across the Internet. It has four layers, and it is the model real networks use.

Application
Covers OSI layers 7, 6 and 5: Application, Presentation and Session. HTTP, DNS, SMTP live here.
Transport
Same as OSI layer 4. TCP and UDP.
Internet
Same as OSI layer 3. IP, ICMP.
Network access
Covers OSI layers 2 and 1: Data Link and Physical. Ethernet, Wi-Fi.

The unit rules

TDM: time-division multiplexing

Tap a formula to see what each letter means.

Slot rate (your rate)R ÷ N?

How many bits per second one connection gets. Also called the circuit rate.

R
the link rate: total speed of the whole link, in bits per second
N
number of slots in each frame = number of connections sharing the link

Example1.536 Mbps link, 24 slots: 1,536,000 ÷ 24 = 64,000 bps (64 kbps).

Your turn comes the same number of times per second (the frame rate), however many connections share the link. What changes is how much you send per turn: more connections means shorter slots, fewer bits per turn, and a lower slot rate. Example: 4 connections on 1 Mbps get 250 kbps each; 8 connections get 125 kbps each.

Slot rate, the other wayframe rate × bits per slot?

The same slot rate, worked out from how often your slot comes round.

frame rate
how many frames (full rounds of turns) happen per second
bits per slot
how many bits you send in each of your turns

Example8,000 frames/s × 8 bits = 64,000 bps, the same as 1,536,000 ÷ 24.

Frame rate = how many turns you get per second (never changes). Bits per slot = how much you send each turn (shrinks as more connections join). Slot rate = turns × bits per turn.

Total time to send a filesetup + F ÷ slot rate?

How long a whole file takes over a TDM circuit, from start to finish.

setup
circuit setup time, in seconds (ms ÷ 1,000)
F
file size, in bits
slot rate
your rate, R ÷ N, not the link rate
